# RFCs

Proposals for changes big enough to need a design before code: new features that touch the database, security or the design system. Small changes go straight to a pull request.

## Statuses

| Status | Meaning |
|---|---|
| Draft | Being written; open for comments. |
| Accepted | Agreed; ready to build. |
| Parked | Designed but deliberately not being built yet. Each says when to revisit it. |
| Implemented | Built and shipped; the RFC links the pull requests. |
| Rejected | Decided against; the RFC says why. |

## Writing one

Copy the shape of an existing RFC: a status table, summary, motivation, goals and non-goals, how things work today, the proposed design, security and privacy, alternatives considered, effort, rollout and open questions. Number them in order (`0002-short-name.md`) and add a row above.
